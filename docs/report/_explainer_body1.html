Draft-aligned decoding of a 30B diffusion model

A small model writes the block. A 39-million-parameter adapter teaches the big model to judge it. This is what the mechanism is, why it should work, and what actually happened.

Read this before the numbers

The trained judge ties the training-free baseline; it does not beat it. The best trained setting reaches 94.0% accuracy at 7.93 passes per block. 01

The machine you are trying to speed up

Everything downstream follows from three facts about how this particular model writes text. None of them hold for an ordinary autoregressive LLM.

It writes 32 tokens at a time, not one. SDAR-30B-A3B-Chat-b32 is a block-diffusion language model. It takes a block of 32 empty slots, each holding a special [MASK] token, and runs one forward pass over the whole sequence. That pass produces a probability distribution over the full 151,936-token vocabulary at every one of the 32 slots simultaneously, each conditioned on the prompt, on all previously finished blocks, and on whatever is currently sitting in the other 31 slots.

It commits only where it is already sure. After the pass, a slot is filled in permanently if its top token's probability exceeds 0.95. Everything else stays [MASK] and is looked at again next pass. At least one slot is forced to commit per pass so the loop cannot stall. Repeat until the block is full, then run one more forward pass to write the finished block into the key/value cache. I will call each of these forwards a pass.

Each pass is expensive in a specific way. The model is a mixture of experts: 48 layers, and in each layer 128 separate feed-forward "experts", of which each token position picks its own top 8. With 32 positions × 8 picks per layer, the union of experts that must actually be loaded from memory is far larger than 8 — measured at 43.1 experts per layer when the block is all masks, and 64.5 when it is full of tokens. Since the weights of an expert must be fetched to run it, the honest cost unit is the expert-layer execution: one expert, running at one layer, in one pass. Divided by the tokens the model actually produced, this is the number to reduce.

02

Why it takes nine passes when one would do

The block does not need nine passes because the model is unsure what to say. It needs nine passes because of the difference between a marginal and a conditional distribution.

Consider one slot in the middle of an otherwise empty block. The model is being asked: what token goes here, given the prompt and given that everything around it is still unknown? The text could continue "So the total is", or "Therefore the total is", or "The total is therefore". All three are correct. The model's probability splits across them — 0.4 / 0.35 / 0.25, say. Nothing reaches 0.95, so nothing commits, even though any of the three would have been fine.

Formally, the distribution at an open slot is a marginal over every completion of the block that is consistent with what has been committed:

p(xi | committed) = Σrest p(xi, rest | committed) ← flat wherever phrasing is free p(xi | committed, rest = D) ← peaked: one concrete completion to judge

A slot whose token is forced by the prefix — the second digit of "10 × 2 = 20" — gets 0.99 and commits immediately. So pass 1 commits only the forced slots, on average 7.5 of the 29.4 generated slots in a block. Each commit then forces a few more slots, which commit next pass, which force a few more. That chain is the nine passes.

The waste is measurable and large. At pass 1 the model's own top guess already equals the token the block eventually ends with at 58.4% of slots — but only 25.6% of slots pass the threshold. A third of all tokens in the finished text are right at pass 1 and committed later anyway, purely because the marginal was too flat to clear 0.95.

The second line of the equation is the whole idea. If some other process proposes one concrete completion D for the rest of the block, then every slot becomes a conditional question — "is this token right, given these specific neighbours?" — and conditional questions are peaked where marginal ones are flat. Judging is easy where generating is hard.

03

The proposal: a 1.7B model writes the block first

A small dense model of the same family, SDAR-1.7B-Chat-b32, fills all 32 slots in 8 of its own cheap denoising steps. Its guess D becomes the concrete completion the big model conditions on.

Agreement 0.558 means: for a randomly chosen slot, the 1.7B's token is the token the 30B eventually writes there, 55.8% of the time. That number is the hard ceiling on how much any draft-based scheme can save, and it is also why this is not classical speculative decoding — more on that below.

The cost arithmetic is favourable and simple. Eight drafter forwards cost 8 × 18 = 144 ms, against 369 ms for a single forward of the big model on an empty block. So the entire draft costs about 0.4 of one big-model pass. The draft is worth it if it removes more than about half a pass out of 9.31. The target was to remove five or six.

Why this is not speculative decoding

In classical speculative decoding the big model is autoregressive, so its output at position i is by construction a judgement of the token at i+1, produced without having seen it. The verifier is free, exact, and acceptance is a prefix: reject the third drafted token and the fourth is discarded too, because it assumed the third. At 56% agreement the accepted prefix averages about two tokens — which is what earlier work on this branch found.

Here the big model has bidirectional attention inside the block. There is no free verifier, but acceptance is per slot: the judge reads all 32 at once, so its verdict on slot 20 can be right when slot 17 was wrong. At 56% agreement that is ~18 slots per pass instead of ~2. That is the prize, and it is exactly what a causal verifier cannot deliver.
