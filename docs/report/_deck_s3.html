Chapter III · the obstacle

Where the draft tokens actually go

Not just before the judged slot, and not everywhere. It alternates.

Every slot is masked in exactly one of the two forwards, and read there. Why not fill all 31 neighbours instead? That would give each judged slot the full draft as context, but at 32 forwards per block rather than 2. The price of the cheap version is that a judged slot only ever sees half the draft.

But C is exactly the flat marginal from chapter I. It never sees the draft, so it stays blurred wherever phrasing is free. It is honest and weak by construction — there is a hard ceiling on it that no threshold can lift.

Which leaves the conclusion the whole project rests on: the ability "judge whether this token belongs in this slot, given its neighbours" does not exist anywhere in the frozen model. There is nothing to extract, so no threshold, vote or prompt can extract it. If we want it, we put it there.

Chapter IV · the dataset

How a row is made, and one real one

Why decode with the free rule rather than plain stock? Its answers are stock-accurate (95.0 against 95.0 on the validation prompts, 90.4 against 90.2 on the frozen test) and they already contain the draft tokens the big model found acceptable. A judge trained on them learns to accept rather than to rewrite.
